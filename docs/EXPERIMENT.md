# 실험 설계

## 질문

비표준 주소 매핑 테이블이 100건에서 1천만 건으로 커질 때, LCS 전수 탐색과 Elasticsearch n-gram 검색의 지연시간과 검색 정확도는 어떻게 달라지고, 어느 규모부터 역색인이 유리해지는가?

## 독립 변수

- 데이터 규모: 100건 / 10,000건 / 100,000건 / 1,000,000건 / 10,000,000건
- 검색 방식: 모든 후보를 비교하는 LCS(Java) / Elasticsearch 2~4-gram 역색인
- 오류 유형: 공백 제거, 행정구역 축약, APT 표기, 한 글자 삭제, 한 글자 치환

## 통제 조건

- 동일 seed로 만든 동일 데이터와 질의 사용
- 두 방식에 같은 질의 집합과 같은 Top-5 평가 기준 적용
- warm-up 10건 후 측정. 두 방식 직접 비교는 앞 100개 질의, Elasticsearch 단독 측정은 1,000개 질의
- LCS 기준선은 적재 시 alias를 한 번만 정규화하고, 질의마다 후보 전체와 LCS 유사도를 계산해 Top-5 힙을 유지
- 정확도는 응답 시간이 아니라 정답 ID로만 판정
- 최종 발표용 수치는 동일 머신에서 다른 고부하 프로세스를 중지하고 최소 3회 반복

## 측정 지표

- Top-1 accuracy, Top-5 accuracy, MRR
- p50/p95/p99 latency, throughput(QPS)
- Elasticsearch 인덱싱 시간과 인덱스 크기

지연시간은 각 구현이 검색 호출 자체만 잽니다. LCS는 정규화·전수 비교·정렬까지, Elasticsearch는 HTTP 요청부터 응답 수신까지입니다. 결과 JSON 파싱은 포함하지 않습니다.

## 해석 주의

데이터는 개인정보가 없는 합성 데이터다. 결과는 OCR 모델 정확도가 아니라 이미 추출된 문자열을 표준 주소에 연결하는 **후처리 검색 품질**을 뜻한다. Java 기준선은 Python 기준선보다 훨씬 빠르므로 두 언어의 수치를 섞어 비교하지 않는다. 중단된 실행을 정확한 결과처럼 보고하지 않고 완료 질의 수와 중단 기준을 기록한다.
